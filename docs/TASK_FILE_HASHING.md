# ТЗ: SHA-256 хеширование файлов при деплое

**Связанный RFC:** `deployment/docs/rfc/EDGE_CONTENT_HASH_CACHE.md` (v3)

---

## Цель

При деплое CLI должен вычислять SHA-256 хеш каждого загружаемого файла и передавать его серверу вместе с path и size. Сервер использует эти хеши для дедупликации кеша edge-server между деплоями — неизменённые файлы отдаются из кеша без обращения к S3.

## Что нужно сделать

### 1. Вычислять SHA-256 каждого файла

- Хеш вычисляется от **оригинального содержимого файла с диска** (до Brotli-сжатия)
- Момент хеширования: при чтении файла в `scan_and_maybe_compress`, до вызова `brotli_compress`
- Формат: hex-encoded строка, 64 символа (например `a3f7c9d2e1b4...`)

**Важно:** именно от оригинала, не от сжатого. Это гарантирует что один и тот же `logo.png` даёт одинаковый хеш вне зависимости от:
- Флага `--no-compress`
- Уровня/настроек Brotli
- Будущей смены алгоритма сжатия

### 2. Передавать хеш в FileEntry

`FileEntry` расширяется полем `sha256`:

```rust
struct FileEntry {
    path: String,
    size: u64,
    sha256: String,  // NEW
}
```

Это поле сериализуется в JSON и отправляется на сервер в `prepare-upload`.

### 3. Без изменений в upload flow

- Presigned URLs, параллельный upload, upload-complete — всё как есть
- SHA-256 только добавляется к metadata, не влияет на загрузку
- Если по какой-то причине хеш невозможно вычислить — не отправлять поле (сервер обработает отсутствие gracefully)

## Ожидаемое поведение

```
$ nrz deploy
  Scanning files...
  Found 150 files (4.2 MB)
  Uploading... ████████████ 150/150
  Deploy complete: https://my-app.onreza.app

# Внутренне: каждый файл в prepare-upload содержит sha256
# POST /v1/deployments/:id/prepare-upload
# body.files = [
#   { "path": "index.html", "size": 1842, "sha256": "e3b0c44298..." },
#   { "path": "logo.png", "size": 8192, "sha256": "a1b2c3d4e5..." },
#   ...
# ]
```

Для пользователя ничего не меняется — деплой работает как раньше. Хеширование происходит параллельно с чтением файлов, overhead = ~0.

## Performance

SHA-256 вычисляется при чтении файла с диска — данные уже в памяти, дополнительного I/O нет. Для типичного SPA (150 файлов, 4MB total) хеширование занимает <10ms. Для крупных проектов (10K файлов, 500MB) — <1s, параллельно с upload.

## Зависимости

- **Server** должен принимать `sha256` в FileEntry и записывать в `deployment_file_hash` таблицу (реализуется в deployment repo)
- **Обратная совместимость:** если server не знает про `sha256` — игнорирует лишнее поле. Если CLI не шлёт `sha256` — server работает без хешей. Но на практике CLI и server обновляются одновременно.
